一、内存管理

1.1 C++ 内存布局

程序运行时的内存分布（从高地址到低地址）：

┌─────────────────┐  高地址
│     栈（Stack）    │  ← 局部变量、函数参数（编译器自动管理）
├─────────────────┤
│     堆（Heap）     │  ← new/malloc 分配（程序员手动管理）
├─────────────────┤
│  全局/静态存储区   │  ← 全局变量、static 变量
│  .data（已初始化） │
│  .bss（未初始化）  │
├─────────────────┤
│  常量存储区 .rodata│  ← 字符串常量、const 全局变量
├─────────────────┤
│   代码区 .text     │  ← 可执行机器指令
└─────────────────┘  低地址

各区域特点：

区域 管理方式 大小 生命周期
栈 编译器自动分配释放 小（默认 ~1MB） 函数结束时
堆 程序员手动管理 大（虚拟内存） 直到 delete/free
全局/静态区 程序启动分配，结束释放 取决于变量 整个程序运行期
常量区 只读，不可修改 取决于常量 整个程序运行期
代码区 只读 取决于代码 整个程序运行期

堆和栈的区别：

栈 堆
生长方向 向下（地址减小） 向上（地址增加）
分配方式 静态分配（编译器）+ 动态分配（alloca） 仅动态分配
分配效率 高（有专门的寄存器指令） 低（库函数搜索空闲内存）
碎片 无碎片 可能产生内存碎片
典型问题 栈溢出（递归过深） 内存泄漏、野指针

1.2 内存泄漏

定义：申请的内存空间使用完毕后没有释放，导致该内存无法再被访问和回收。

类型：

  • 堆内存泄漏：new/malloc 后没有 delete/free
  • 系统资源泄漏：socket、handle、Bitmap 等系统资源未释放

检测工具：

  • Valgrind（Linux）
  • Visual Studio 诊断工具（Windows）
  • Dr.Memory

如何避免：

  • 使用智能指针（unique_ptr、shared_ptr）
  • RAII 机制（资源获取即初始化）
  • 规范配对使用 new/delete、malloc/free

1.4 野指针和空指针

野指针（Wild Pointer）：未被初始化的指针。指向不确定的内存地址。

空指针（Dangling Pointer）：原指向的内存已被释放，但指针未被置空。

1
2
3
4
5
6
7

int* p;               // 野指针：未初始化
// *p = 10;           // 危险！

int* q = new int(5);
delete q;
// *q = 10;           // 空指针：内存已释放
q = nullptr;           // 安全：释放后置空

如何避免：

  • 定义指针后立即初始化
  • 释放内存后立即将指针置为 nullptr
  • 优先使用智能指针

二、智能指针

2.1 为什么需要智能指针

智能指针是一个类，当超出作用域时自动调用析构函数释放资源，避免手动 delete 导致的内存泄漏。

核心机制：RAII（Resource Acquisition Is Initialization，资源获取即初始化）。

2.2 四种智能指针

（1）auto_ptr（C++11 已废弃）：采用所有权模式，存在潜在的内存崩溃问题。

1
2
3

auto_ptr<string> p1(new string("hello"));
auto_ptr<string> p2;
p2 = p1;  // p1 失去所有权，再次访问 p1 会崩溃

（2）unique_ptr（独占所有权）：同一时刻只能有一个 unique_ptr 指向对象，禁止拷贝但支持移动。

1
2
3
4
5
6

unique_ptr<string> p1(new string("hello"));
// unique_ptr<string> p2 = p1;     // 编译错误！禁止拷贝
unique_ptr<string> p2 = move(p1);  // 转移所有权，p1 变为空

// 推荐：使用 make_unique（C++14）
auto p = make_unique<string>("hello");

（3）shared_ptr（共享所有权）：多个 shared_ptr 可指向同一对象，通过引用计数管理生命周期。

shared_ptr<int> p1 = make_shared<int>(42);
{
    shared_ptr<int> p2 = p1;  // 引用计数 +1
    cout << p1.use_count();   // 输出 2
}  // p2 析构，引用计数 -1
// p1 析构时引用计数归零，释放内存

// 引用计数存储在控制块（Control Block）中：
// - 强引用计数：shared_ptr 数量
// - 弱引用计数：weak_ptr 数量
// - 删除器、分配器

shared_ptr 的线程安全：

  • 引用计数的增减是原子操作（线程安全）
  • 对同一 shared_ptr 实例的写操作（如 reset()）不是线程安全的
  • 对管理对象的直接访问需要外部同步

（4）weak_ptr（弱引用）：不控制对象生命周期，配合 shared_ptr 解决循环引用问题。

2.3 智能指针的缺点

缺点 说明 解决方案
性能开销 引用计数需要原子操作 优先用 unique_ptr
循环引用 shared_ptr 相互引用 使用 weak_ptr 打破
线程安全代价 原子操作有性能损耗 无跨线程共享时用局部 shared_ptr
与裸指针混用 可能导致悬垂指针 避免暴露裸指针

三、指针和引用

3.1 指针和引用的区别

指针（Pointer） 引用（Reference）
本质 实体，存储地址值 别名，不占用独立存储

可修改 可改变指向 绑定后不可改变
空值 可为 nullptr 不能为空
const 有 const 和非 const 区别 无此概念
sizeof 指针本身的大小（64位=8字节） 所引用对象的大小
运算 支持算术运算（++、–） 不支持
使用 需要解引用 *p 直接使用

4.3 多态

三要素：继承、方法重写（virtual）、父类引用指向子类对象。

静态多态（编译时）：函数重载、模板。编译时期决定调用的函数。

动态多态（运行时）：通过虚函数实现。运行时期根据对象实际类型决定调用的函数。

4.4 虚函数原理（虚函数表）

虚函数表（vtable）：当类中包含虚函数时，编译器为每个类生成一个虚函数表，保存该类中所有虚函数的地址。

虚函数指针（vptr）：每个包含虚函数的类的对象有一个隐藏的虚函数指针，指向该类的虚函数表。vptr 在构造函数中初始化。

class Base {
public:
    virtual void func1() { cout << "Base::func1"; }
    virtual void func2() { cout << "Base::func2"; }
};

class Derived : public Base {
public:
    virtual void func1() override { cout << "Derived::func1"; }
    virtual void func3() { cout << "Derived::func3"; }
};

┌─────────────┐
│ vptr → Base │  ← 指向 Base 的虚函数表

│ vtable       │
│   func1 ─────┼──→ Derived::func1（重写，覆盖基类地址）
│   func2 ─────┼──→ Base::func2（未重写，保留基类地址）
│   func3 ─────┼──→ Derived::func3（新增）
└─────────────┘

编译器处理虚函数表的步骤：

  1. 拷贝基类的虚函数表（多继承则拷贝多个）
  2. 如果派生类重写基类虚函数，替换为已重写的函数地址
  3. 如果派生类有自身虚函数，追加到自身的虚函数表中

4.5 析构函数为什么一般定义为虚函数 

1
2

Base* p = new Derived();
delete p;  // 如果析构函数不是虚函数，只会调用 Base 的析构，Derived 的资源泄漏

原因：基类指针指向派生类对象时，如果析构函数不是虚函数，编译器根据指针类型（Base）调用析构函数，派生类的资源无法释放，造成内存泄漏。定义为虚函数后，根据实际对象类型调用，先执行派生类析构，再执行基类析构。

4.6 构造函数为什么一般不定义为虚函数

  1. 虚函数调用需要知道对象的具体类型，但构造函数调用时对象还未创建
  2. 虚函数通过 vptr 调用，但 vptr 是在构造函数中才初始化的
  3. 从设计角度，构造函数是为了创建对象，不应该被重写

// 纯虚函数：在基类中声明但不实现，派生类必须重写
class Shape {
public:
    virtual double area() const = 0;  // 纯虚函数
    virtual void draw() const = 0;
};

// 含有纯虚函数的类称为抽象类，不能实例化
// Shape s;  // 编译错误！

class Circle : public Shape {
public:
    double area() const override { return 3.14 * r * r; }
    void draw() const override { cout << "画圆形"; }
private:
    double r;
};

纯虚函数的目的：让派生类只继承函数的接口（interface），派生类必须提供实现。

5.2 重写（Override）

派生类重新定义基类的虚函数，函数名、参数列表、返回值必须完全相同。

1

class Base {
public:
    virtual void func() { cout << "Base"; }
};

public:

};

override（C++11）：显式标记重写，编译器会检查是否真的重写了基类虚函数，避免因签名不一致导致的隐藏。

final（C++11）：禁止类被继承，或禁止虚函数被重写。

};

    // 若需要修改某个成员，用 mutable
    mutable int cache;
    int getCache() const { return cache++; }  // mutable 可在 const 函数中修改
};

7.1 深拷贝和浅拷贝

浅拷贝：默认拷贝构造函数，逐字节复制成员。如果成员有指针，两个对象指向同一块内存，析构时会重复释放。

深拷贝：显式定义拷贝构造函数，为指针成员在堆上分配新内存。

class String {
private:
    char* data;
public:
    // 浅拷贝（默认）：两个 String 的 data 指向同一块内存
    // String(const String& other) : data(other.data) { }

    // 深拷贝：分配新内存
    String(const String& other) {
        data = new char[strlen(other.data) + 1];
        strcpy(data, other.data);
    }

    ~String() {
        delete[] data;
    }

    // 赋值运算符也需要深拷贝
    String& operator=(const String& other) {
        if (this == &other) return *this;  // 自赋值检查
        delete[] data;
        data = new char[strlen(other.data) + 1];
        strcpy(data, other.data);
        return *this;
    }
};

何时必须用深拷贝：类中包含指针成员、动态分配的资源、文件句柄等。

class Person {
    char* data;
public:
    // 移动构造函数：从右值中"偷"资源
    Person(Person&& other) noexcept {
        data = other.data;         // 偷取指针
        other.data = nullptr;      // 原对象置空，防止双重释放
    }

    // 移动赋值运算符
    Person& operator=(Person&& other) noexcept {
        if (this != &other) {
            delete[] data;
            data = other.data;
            other.data = nullptr;
        }
        return *this;
    }
};

九、STL 容器

9.1 vector 扩容机制

触发条件：插入元素时 size 超过 capacity。

扩容策略：

  • GCC：新容量 = 旧容量 × 2
  • MSVC：新容量 = 旧容量 × 1.5

扩容步骤：

  1. 分配更大的连续内存块
  2. 将旧元素移动/拷贝到新内存
  3. 释放旧内存
  4. 更新内部指针

时间复杂度：分摊 O(1)（每次插入的平均成本）。

迭代器失效：扩容后所有迭代器、指针、引用均失效。

// → push_back → capacity=4 → push_back → capacity=8 ...

9.2 list 和 vector 的区别

vector list

9.3 红黑树（RB-Tree）

定义：一种自平衡的二叉查找树，确保没有一条路径比其他路径长出两倍。

性质：

  1. 每个节点是红色或黑色
  2. 根节点是黑色
  3. 叶节点（NIL）是黑色
  4. 红色节点的子节点必须是黑色
  5. 任一节点到每个叶子的路径包含相同数量的黑节点

应用：C++ STL 中的 std::map、std::set 底层基于红黑树。

和 AVL 树的对比：红黑树是弱平衡，旋转次数少，适合插入/删除频繁的场景。

十一、内存池

定义：预先分配一块大内存，将其划分为多个固定大小的块，程序从池中分配和释放，减少频繁 new/delete 的开销和内存碎片。

优点：

  • 减少系统调用
  • 避免内存碎片
  • 分配速度快（O(1)）

class MemoryPool {
private:
    struct Block {
        Block* next;
    };
    Block* freeList = nullptr;

public:
    MemoryPool(size_t blockSize, size_t count) {
        for (size_t i = 0; i < count; i++) {
            Block* block = reinterpret_cast<Block*>(new char[blockSize]);
            block->next = freeList;
            freeList = block;
        }
    }

    void* allocate() {
        if (!freeList) throw bad_alloc();
        Block* block = freeList;
        freeList = freeList->next;
        return block;
    }

    void deallocate(void* ptr) {
        Block* block = reinterpret_cast<Block*>(ptr);
        block->next = freeList;
        freeList = block;
    }
};

十四、面试高频问答

14.1 程序是怎样跑起来的

  1. 编译阶段：预处理 → 编译 → 汇编 → 链接，生成可执行文件
  2. 进程创建：操作系统分配虚拟地址空间，加载代码段和数据段
  3. 初始化：设置堆栈，初始化全局变量，调用全局对象的构造函数
  4. 入口点：跳转到 _start，最终调用 main()
  5. 执行：CPU 逐条执行指令，通过 MMU 将虚拟地址映射为物理地址
  6. 系统调用：需要操作系统服务时（如 IO），进入内核态执行
  7. 结束：程序执行完，操作系统回收资源
