一、MonoBehaviour 生命周期

1.1 生命周期执行顺序

Unity 中每个 MonoBehaviour 脚本从唤醒到销毁有固定的执行顺序：

  ↓

  ↓
渲染
  ↓
OnDisable（对象禁用时调用）
  ↓
OnDestroy（对象销毁时调用）

1.2 各方法详解

Awake：用于初始化自身状态，不依赖其他对象。在所有对象初始化完成后调用，可安全使用 GameObject.FindWithTag。不可用于协程。

Start：在 Awake 之后、第一次 Update 之前调用。适合做依赖其他对象的初始化（如获取其他组件引用）。

OnEnable：每次对象被激活时调用。与 OnDisable 成对出现，可在同一生命周期中反复发生。

    }

    void OnDisable()
    {
        // 每次禁用时取消注册
        InputManager.OnJump -= Jump;
    }
}

1.3 Update、FixedUpdate、LateUpdate 的区别

方法 执行频率 用途 特点
FixedUpdate 固定 0.02s（可配置） 物理相关（刚体力、碰撞） 时间间隔固定，不受帧率影响，一帧内可能调用多次
Update 每帧一次（约 0.0167s @60FPS） 非物理逻辑（输入检测、状态更新） 执行间隔不固定，受帧率波动影响
LateUpdate Update 全部完成后 依赖其他对象更新后的逻辑（摄像机跟随） 确保所有对象的移动和状态已更新

二、协程（Coroutine）

2.1 协程的本质

协程是 Unity 中分段执行代码逻辑的机制。它通过 yield return 将方法拆分为多个片段，在特定条件满足后恢复执行。

协程不是多线程：协程完全运行在主线程上，只是通过分帧执行模拟"并行"效果。

协程的底层原理：基于 C# 的迭代器特性。调用 StartCoroutine() 时，Unity 将协程包装为状态机，在每帧的 Update 之后检查 yield 条件是否满足，满足则通过 MoveNext() 推动协程执行到下一个 yield 或结束。

public class CoroutineExample : MonoBehaviour
{
    void Start()
    {
        // 启动协程
        StartCoroutine(DelaySpawnEnemy());
        StartCoroutine(LoadSceneAsync());
    }

    // 延迟执行
    IEnumerator DelaySpawnEnemy()
    {
        yield return new WaitForSeconds(3);  // 等待3秒
        Instantiate(enemyPrefab, spawnPoint.position, Quaternion.identity);
    }

    // 分帧加载资源
    IEnumerator LoadSceneAsync()
    {
        AsyncOperation asyncLoad = SceneManager.LoadSceneAsync("Level2");
        while (!asyncLoad.isDone)
        {
            float progress = asyncLoad.progress;
            UpdateLoadingUI(progress);
            yield return null;  // 每帧更新进度
        }
    }

    // 序列动画
    IEnumerator FadeOut(SpriteRenderer renderer)
    {
        Color color = renderer.color;
        while (color.a > 0)
        {
            color.a -= Time.deltaTime * 0.5f;
            renderer.color = color;
            yield return null;  // 每帧更新透明度
        }
    }
}

2.2 常用 yield 指令

指令 作用
yield return null 等待下一帧
yield return new WaitForSeconds(n) 等待 n 秒
yield return new WaitForEndOfFrame() 等待帧结束
yield return new WaitForFixedUpdate() 等待物理帧更新
yield return new WaitUntil(() => 条件) 等待条件为 true
yield return new WaitWhile(() => 条件) 等待条件为 false
yield return StartCoroutine(Other()) 等待另一个协程完成

2.3 协程的注意事项

  • 生命周期：协程依附于 MonoBehaviour，对象销毁时协程自动停止
  • 性能：协程本身开销极低，但频繁 yield return new 会产生 GC 垃圾
  • 优化：复用 WaitForSeconds 对象，避免每次创建

三、对象池（Object Pool）

3.1 为什么需要对象池

频繁 Instantiate 和 Destroy 会产生大量的 GC 压力和内存碎片。对象池通过复用对象来避免这个问题。典型场景：子弹、敌人、特效。

public class ObjectPool : MonoBehaviour
{
    [SerializeField] private GameObject prefab;
    private Queue<GameObject> pool = new Queue<GameObject>();

    // 从池中获取对象
    public GameObject Get()
    {
        if (pool.Count > 0)
        {
            GameObject obj = pool.Dequeue();
            obj.SetActive(true);
            return obj;
        }
        // 池中没有可用对象，创建新对象
        return Instantiate(prefab);
    }

    // 将对象归还池中
    public void Return(GameObject obj)
    {
        obj.SetActive(false);
        pool.Enqueue(obj);
    }
}

using UnityEngine.Pool;

public class BulletPool : MonoBehaviour
{
    [SerializeField] private GameObject bulletPrefab;
    private ObjectPool<Bullet> pool;

    void Start()
    {
        pool = new ObjectPool<Bullet>(
            createFunc: () => Instantiate(bulletPrefab).GetComponent<Bullet>(),
            actionOnGet: (bullet) => bullet.gameObject.SetActive(true),
            actionOnRelease: (bullet) => bullet.gameObject.SetActive(false),
            actionOnDestroy: (bullet) => Destroy(bullet.gameObject),
            collectionCheck: true,
            defaultCapacity: 10,
            maxSize: 100
        );
    }

    public Bullet GetBullet() => pool.Get();

    public void ReturnBullet(Bullet bullet) => pool.Release(bullet);
}

核心方法：

  • Get()：从池中获取对象
  • Release(T)：将对象放回池中

注意事项：

  • 在 actionOnGet 中重置对象状态（位置、速度等）
  • 确保每个 Get() 都有对应的 Release()

四、动态加载资源的方式

4.1 三种加载方式对比

方式 说明 适用场景
Instantiate 直接实例化预制体 最简单，运行时动态生成
Resources.Load 从 Resources 文件夹加载 简单项目，但所有资源都会被打包

五、UGUI 与适配

5.1 Canvas 的三种渲染模式

Screen Space - Overlay（默认）：UI 始终在 3D 元素前面，与摄像机无关。

Screen Space - Camera：UI 通过指定摄像机渲染，支持 3D 效果（如粒子在 UI 前）。

World Space：UI 成为场景中的 3D 物体，可用于怪物血条、VR 开发。

5.2 Canvas Scaler 缩放模式

模式 说明
Constant Pixel Size UI 保持固定像素大小
Scale With Screen Size 根据参考分辨率动态缩放（推荐）
Constant Physical Size 根据物理尺寸（英寸）缩放

5.3 UI 自适应方案

锚点（Anchors）：定义 UI 元素相对于父容器的定位方式。

锚点预设 效果
居中 元素始终居中
拉伸 元素随父容器拉伸

Rect Transform：UI 元素的变换组件，包含锚点、轴心、偏移量等属性。

布局组件：

  • Horizontal/Vertical Layout Group：自动排列子元素
  • Content Size Fitter：根据内容动态调整大小
  • Aspect Ratio Fitter：保持宽高比

public class JoystickController : MonoBehaviour, IDragHandler, IPointerDownHandler, IPointerUpHandler
{
    [SerializeField] private RectTransform joystickBG;
    [SerializeField] private RectTransform joystickHandle;
    private Vector2 inputDirection;

    public Vector2 InputDirection => inputDirection;

    public void OnDrag(PointerEventData eventData)
    {
        Vector2 pos;
        RectTransformUtility.ScreenPointToLocalPointInRectangle(
            joystickBG, eventData.position, eventData.pressEventCamera, out pos
        );
        pos = pos / joystickBG.sizeDelta;  // 归一化
        inputDirection = pos.magnitude > 1 ? pos.normalized : pos;
        joystickHandle.anchoredPosition = inputDirection * joystickBG.sizeDelta;
    }

    public void OnPointerUp(PointerEventData eventData)
    {
        inputDirection = Vector2.zero;
        joystickHandle.anchoredPosition = Vector2.zero;
    }
}

// 摇杆控制角色移动
public class PlayerController : MonoBehaviour
{
    public JoystickController joystick;
    public float moveSpeed = 5f;

    void Update()
    {
        Vector2 input = joystick.InputDirection;
        Vector3 movement = new Vector3(input.x, 0, input.y) * moveSpeed * Time.deltaTime;
        transform.Translate(movement);
    }
}

public class ClickInteraction : MonoBehaviour
{
    private Camera mainCamera;

    void Start() => mainCamera = Camera.main;

    void Update()
    {
        if (Input.GetMouseButtonDown(0))
        {
            Ray ray = mainCamera.ScreenPointToRay(Input.mousePosition);
            RaycastHit hit;

            // 3D 物体检测
            if (Physics.Raycast(ray, out hit))
            {
                Debug.Log("点击了: " + hit.collider.gameObject.name);
            }

            // 2D 物体检测
            RaycastHit2D hit2D = Physics2D.Raycast(ray.origin, ray.direction);
            if (hit2D.collider != null)
            {
                Debug.Log("点击了 2D 物体: " + hit2D.collider.name);
            }
        }
    }
}

八、Unity GC 与优化

8.1 GC 工作机制

Unity 的 GC 采用分代回收策略：

代 特点
Gen 0 新分配的小对象，回收最频繁
Gen 1 Gen 0 幸存对象，回收次之
Gen 2 长期存活对象（如单例），极少回收

GC 触发条件：Gen 0 空间不足时自动触发，或手动调用 System.GC.Collect()（不推荐）。

GC 执行时主线程暂停，导致帧率骤降。

10.2 四元数与旋转

四元数是 Unity 中表示旋转的数学工具，使用四个分量（x, y, z, w）表示三维空间中的旋转。

为什么不用欧拉角：

  • 万向锁：当某个轴旋转 90 度时，另外两个轴失去自由度，导致旋转异常
  • 插值不平滑：欧拉角插值会产生不自然的旋转路径

四元数的优点：

  • 可进行增量旋转（旋转叠加）
  • 避免万向锁
  • 插值平滑（Slerp 球形插值）

public class AIController : MonoBehaviour
{
    private NavMeshAgent agent;
    public Transform target;

    void Start()
    {
        agent = GetComponent<NavMeshAgent>();

        // 配置参数
        agent.speed = 5f;              // 移动速度
        agent.angularSpeed = 120f;     // 旋转速度
        agent.acceleration = 8f;       // 加速度
        agent.stoppingDistance = 1.5f; // 停止距离（攻击范围）

        agent.SetDestination(target.position);
    }

    void Update()
    {
        // 状态检测
        if (!agent.pathPending && agent.remainingDistance <= agent.stoppingDistance)
        {
            // 到达目标，执行攻击逻辑
            Attack();
        }

        // 动态更新目标
        if (target.hasChanged)
        {
            agent.SetDestination(target.position);
        }
    }

    // 暂停/恢复寻路
    public void Pause() => agent.isStopped = true;
    public void Resume() => agent.isStopped = false;

    // 判断是否到达
    public bool HasReached => !agent.pathPending && agent.remainingDistance < 0.1f;
}

十二、相机系统

12.1 相机参数详解

Clear Flags：决定屏幕中未渲染区域的处理方式

  • Skybox：用天空盒填充（3D 场景默认）
  • Solid Color：用纯色填充（2D 游戏，适合像素风）
  • Depth Only：仅清除深度缓冲（用于多相机叠加，如主相机 + 武器相机）
  • Don’t Clear：不清除任何内容（需谨慎使用，会产生拖影效果）

Projection：投影模式

  • Perspective：透视投影，近大远小，适合 3D 游戏
    • Field of View（FOV）：视野角度，默认 60°，FPS 游戏通常用 90°
  • Orthographic：正交投影，无视距离，适合 2D 游戏、UI 相机
    • Size：视野高度的一半（单位：unity 单位）

Clipping Planes：

  • Near：近剪裁面，过小会导致物体被"挖穿"（z-fighting）
  • Far：远剪裁面，过大影响性能（深度精度下降）

进阶参数：

  • Viewport Rect：定义相机渲染的屏幕区域（分屏合作游戏）
    • X=0, Y=0, W=0.5, H=1 → 左半屏（玩家1）
    • X=0.5, Y=0, W=0.5, H=1 → 右半屏（玩家2）
  • Culling Mask：每层 32 位掩码，选择渲染哪些 Layer 的物体
  • Target Texture：将相机画面渲染到 Render Texture（小地图、监控摄像头）

13.4 ECS 架构（Entity-Component-System）

ECS 是数据导向的架构，将面向对象的"对象 = 数据 + 行为"拆分为纯数据和纯逻辑。

为什么需要 ECS：

  • 传统 OOP 中，10000 个敌人各自执行 Update，CPU 缓存命中率低
  • ECS 将同类数据连续存储，CPU 遍历时按顺序读取，性能提升数倍

核心概念：

概念 说明 类比 OOP
Entity（实体） 唯一 ID，无数据无方法 GameObject

using Unity.Entities;
using Unity.Burst;
using Unity.Jobs;
using Unity.Mathematics;

// Component：纯数据结构
public struct Position : IComponentData
{
    public float3 Value;
}

public struct Velocity : IComponentData
{
    public float3 Value;
}

// System：每帧处理所有具有 Position + Velocity 的 Entity
[BurstCompile]
public partial struct MovementSystem : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        // 查询所有拥有 Position 和 Velocity 的 Entity
        foreach (var (position, velocity) in
            SystemAPI.Query<RefRW<Position>, RefRO<Velocity>>())
        {
            // 更新位置：position += velocity * deltaTime
            position.ValueRW.Value += velocity.ValueRO.Value * SystemAPI.Time.DeltaTime;
        }
    }
}

// 创建 Entity 并添加组件
public class GameManager : MonoBehaviour
{
    void Start()
    {
        var world = World.DefaultGameObjectInjectionWorld;
        var entityManager = world.EntityManager;

        // 批量创建 10000 个移动实体
        for (int i = 0; i < 10000; i++)
        {
            Entity entity = entityManager.CreateEntity();
            entityManager.AddComponentData(entity, new Position { Value = float3.zero });
            entityManager.AddComponentData(entity, new Velocity { Value = new float3(1, 0, 0) });
        }
    }
}

14.1 动画层（Animation Layers）

实现"边跑边射击"的核心技术是动画分层。将身体分为上下两层，分别播放不同动画。

实现步骤：

  1. 在 Animator Controller 中创建两个 Layer：

    • Base Layer：处理移动动画（走、跑、跳跃）
    • Upper Body Layer：处理上身动画（射击、换弹、投掷）

  2. 为 Upper Body Layer 设置 Avatar Mask：

    • 创建 Avatar Mask 资产
    • 仅勾选上半身骨骼（Spine、Chest、Left/Right Arm、Head）
    • 下半身骨骼交由 Base Layer 控制

public class PlayerAnimator : MonoBehaviour
{
    private Animator animator;

    // 动画层索引
    private readonly int baseLayer = 0;
    private readonly int upperLayer = 1;

    void Start() => animator = GetComponent<Animator>();

    void Update()
    {
        // Base Layer：根据速度切换走/跑
        float speed = new Vector2(Input.GetAxis("Horizontal"), Input.GetAxis("Vertical")).magnitude;
        animator.SetFloat("Speed", speed);

        // Upper Body Layer：射击时启用
        if (Input.GetButtonDown("Fire1"))
        {
            // 将 Upper Body 权重设为 1（完全覆盖上半身）
            animator.SetLayerWeight(upperLayer, 1f);
            animator.Play("Shoot", upperLayer, 0f);
        }

        // 射击结束后逐渐恢复权重为 0
        if (Input.GetButtonUp("Fire1"))
        {
            StartCoroutine(FadeOutLayer(upperLayer, 0.2f));
        }
    }

    IEnumerator FadeOutLayer(int layer, float duration)
    {
        float elapsed = 0;
        while (elapsed < duration)
        {
            elapsed += Time.deltaTime;
            animator.SetLayerWeight(layer, Mathf.Lerp(1, 0, elapsed / duration));
            yield return null;
        }
        animator.SetLayerWeight(layer, 0);
    }
}

十五、Unity 序列化

15.1 什么是序列化

序列化将对象状态转换为可存储或可传输的格式（二进制、JSON、XML），反序列化则逆向还原。

Unity 中的序列化场景：

场景 说明
场景和预制体保存 Inspector 中修改的 public 变量自动序列化到 .unity / .prefab 文件
Inspector 面板显示 [SerializeField] 让私有变量显示在 Inspector 并序列化
ScriptableObject 创建可复用配置数据，保存为 .asset 文件
JSON 存档 使用 JsonUtility 序列化游戏存档
网络传输 序列化对象状态发送到服务器或其他客户端

15.2 序列化规则

Unity 自动序列化以下类型：

  • 基本类型：int, float, string, bool, enum
  • Unity 结构体：Vector2/3/4, Quaternion, Color, Rect, Bounds
  • 引用类型：GameObject, Component, ScriptableObject（序列化引用而非内容）
  • 数组和 List<T>（T 必须是可序列化类型）
  • 自定义类/结构体：需标记 [System.Serializable]

不会被序列化的成员：

  • 静态变量
  • 属性（Property，有 get/set 的成员）
  • 委托和事件
  • 接口类型
  • 字典 Dictionary（需手动处理）

// 保存存档
public class SaveManager : MonoBehaviour
{
    public void SaveGame(GameSaveData data)
    {
        string json = JsonUtility.ToJson(data, true);  // true = 格式化输出
        File.WriteAllText(Application.persistentDataPath + "/save.json", json);
    }

    public GameSaveData LoadGame()
    {
        string path = Application.persistentDataPath + "/save.json";
        if (File.Exists(path))
        {
            string json = File.ReadAllText(path);
            return JsonUtility.FromJson<GameSaveData>(json);
        }
        return null;
    }
}

public class Inventory : MonoBehaviour, ISerializationCallbackReceiver
{
    // Dictionary 不会被 Unity 自动序列化
    [NonSerialized] public Dictionary<string, int> items = new Dictionary<string, int>();

    // 用列表中转存储
    [SerializeField] private List<string> _keys = new List<string>();
    [SerializeField] private List<int> _values = new List<int>();

    // 序列化前：字典 → 列表
    public void OnBeforeSerialize()
    {
        _keys.Clear();
        _values.Clear();
        foreach (var pair in items)
        {
            _keys.Add(pair.Key);
            _values.Add(pair.Value);
        }
    }

    // 反序列化后：列表 → 字典
    public void OnAfterDeserialize()
    {
        items.Clear();
        for (int i = 0; i < _keys.Count; i++)
            items[_keys[i]] = _values[i];
    }
}

（2）使用对象池代替频繁 Instantiate/Destroy：

  • 子弹、敌人、粒子特效等高频创建的对象使用对象池
  • 避免 GC 压力，降低 CPU 峰值

（3）减少 Mono 调用：

  • 每帧调用 Unity API（如 transform.position）有 native/managed 边界开销
  • 缓存频繁访问的 Transform、Renderer 等组件引用

（4）LOD（Level of Detail）：

  • 远处的物体使用低面数模型
  • Unity LOD Group 组件自动切换

16.2 GPU 性能优化

（1）合批（Batching）：

方式 条件 效果
Static Batching 标记为 Static 的物体 减少 Draw Call
Dynamic Batching 小物体（<900顶点） CPU 换 GPU
GPU Instancing 相同 Mesh + Material 的物体 一次绘制多个

（2）减少 Draw Call：

  • 使用图集（Sprite Atlas）合并纹理
  • 尽可能共用材质
  • 使用 Shader 变体控制功能开关

（3）纹理优化：

  • 使用合适的纹理格式（ASTC/ETC2）
  • 开启 Mipmap（远处用低分辨率）
  • 控制最大纹理尺寸（手机 2048 足够）
