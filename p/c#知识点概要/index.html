1.2 运算符

C# 提供丰富的运算符用于数据处理。需要特别注意整数除法的截断行为和 null 条件运算符。

算术运算符：+ - * / %。整数相除会截断小数部分，取余 % 获取除法余数。

比较运算符：== != < > <= >=，返回 bool 值。

逻辑运算符：&& || !。&& 存在短路特性，左侧为 false 时右侧不执行。

null 处理运算符：

  • ??（null 合并）：左侧不为 null 则取左侧，否则取右侧
  • ?.（null 条件访问）：左侧为 null 时不执行后续操作，返回 null

1.3 流程控制

C# 提供四种控制结构。if/else 用于范围判断，switch 用于多分支匹配，for/foreach/while 用于循环。

if/else：条件为 true 时执行对应分支，支持 else if 链式判断。

switch 语句：传统 switch 需要 break 跳出，C# 7+ 支持模式匹配可直接匹配类型。

switch 表达式：C# 8+ 新语法，用 => 取代 case:，更简洁，必须覆盖所有情况。

循环三兄弟：

  • for：知道次数时使用，需初始化、条件、迭代三部分
  • foreach：遍历集合元素，无需关心索引，不能修改集合结构
  • while：条件满足时重复执行，适合不确定次数的场景

1.4 字符串操作

C# 中 string 是引用类型，但具有不可变性——每次修改都会创建新对象。大量拼接时要用 StringBuilder。

字符串不可变：str += "x" 不是修改原字符串，而是创建新对象并让变量指向它。频繁操作会导致大量临时对象。

字符串插值：$"Hello {name}" 比 + 拼接更可读，推荐用于少量拼合。

StringBuilder：当循环内大量拼接时，用 StringBuilder 避免创建中间对象，显著提升性能。

二、面向对象（OOP）

2.1 类与对象

类是 C# 面向对象的基本单位，包含字段、属性、方法、构造函数四种核心成员。

字段 vs 属性：字段是存储数据的变量，属性是对字段的封装（get/set），外部应通过属性访问而不是直接操作字段。自动属性 { get; set; } 由编译器自动生成背后字段。

构造函数：与类同名，创建对象时调用，用于初始化成员。如果不写，编译器提供无参默认构造。

静态成员：属于类本身而非实例，通过类名.成员名直接调用，所有实例共享一份。

只读属性：只提供 get 不提供 set，或如例中 { get; private set; } 外部只读。

// 定义 Person 类
public class Person
{
    // 字段（私有，外部不可访问）
    private string name;

    // 属性（推荐用属性代替公开字段）
    public string Name { get; set; }           // 自动属性，编译器生成背后字段
    public int Age { get; private set; }       // 外部只能读，内部可设置

    // 表达式体属性（只读）
    public bool IsAdult => Age >= 18;

    // 构造函数（创建对象时初始化）
    public Person(string name, int age)
    {
        Name = name;      // 通过属性赋值
        Age = age;
    }

    // 实例方法
    public void Introduce()
    {
        Console.WriteLine($"我是{Name}，{Age}岁");
    }

    // 静态成员（属于类，不属于对象）
    public static string Species = "人类";
}

// 使用类
var p = new Person("张三", 25);  // new 创建实例，调用构造函数
p.Introduce();                    // 调用实例方法
Console.WriteLine(Person.Species); // 通过类名访问静态成员

2.2 封装

封装是 OOP 三大特性之一，将数据和行为绑定，对外隐藏内部细节，通过访问修饰符控制外部访问权限。

封装的目的：保护数据不被外部随意修改，通过方法提供受控的操作入口。

属性访问器：

  • get 读取时执行，可包含逻辑（如计算字段）
  • set 写入时执行，参数 value 表示传入的值
  • 可单独限制 get/set 的访问级别（如 private set）

带验证的属性：在 set 中添加检查逻辑，确保数据合法性。

public class BankAccount
{
    // 私有字段（外部无法直接访问 balance）
    private decimal balance;

    // 属性：提供受控的访问入口
    public decimal Balance
    {
        get { return balance; }          // 读取时直接返回字段
        private set { balance = value; } // 写入权限限制为私有，外部不能改
    }

    // 带验证的属性
    private string accountNumber;
    public string AccountNumber
    {
        get => accountNumber;             // 表达式体 get
        set
        {
            if (value.Length != 10)
                throw new ArgumentException("账号必须10位");
            accountNumber = value;
        }
    }

    // 通过公开方法暴露可受控的操作
    public void Deposit(decimal amount)
    {
        if (amount <= 0) return;          // 业务规则校验
        balance += amount;
    }
}

2.3 继承

继承让子类复用父类的成员，形成层次关系。C# 支持单继承（一个类只能有一个父类），但支持多层传递。

关键字：

  • virtual：父类中标记可被子类重写的方法
  • override：子类重写父类的 virtual 方法
  • base：在子类中调用父类构造函数或方法
  • sealed：阻止进一步继承（类前加 sealed 则不可被继承）

构造链：创建子类对象时，先调用父类构造函数（通过 base），再执行子类构造函数。如果不写 base，隐式调用父类的无参构造。

// sealed 类禁止被继承

{

    {

}

2.4 多态

多态指同一操作在不同对象上产生不同行为。C# 中分为两种：

方法重载（编译时多态）：同类中同名方法但参数不同，编译器根据参数类型和数量决定调用哪个版本。与返回值无关。

方法重写（运行时多态）：通过 virtual/override 实现，运行时根据对象实际类型调用对应方法，而非引用类型。

抽象类 vs 接口：

  • 抽象类：用 abstract 标记，可包含实现和字段，用于"是什么"（is-a 关系）
  • 接口：纯抽象契约，只能声明方法，可多实现，用于"能做什么"（can-do 关系）

public abstract class Shape
{
    public abstract double GetArea();  // 抽象方法，子类必须 override
}

// 接口：纯方法声明
public interface IDrawable
{
    void Draw();  // 接口方法隐式 public abstract

// 一个类可同时继承抽象类并实现多个接口
public class Circle : Shape, IDrawable
{
    public double Radius { get; set; }

    public override double GetArea() => Math.PI * Radius * Radius;
    public void Draw() => Console.WriteLine("画圆形");
}

2.5 泛型

泛型允许在定义类/方法时将类型作为参数，避免为每种类型重复编写代码，同时保持类型安全。

为什么要用泛型：没有泛型时集合只能存 object，导致装箱拆箱和运行时类型错误。泛型在编译时确定类型，无需转换。

泛型类：用 <T> 声明类型参数，类内部所有使用 T 的地方都会被实际类型替换。

泛型方法：可单独给方法指定类型参数，不依赖所在类是否泛型。

泛型约束 where：限制类型参数必须具备的能力（如实现某接口、有无参构造）。

协变 out 与逆变 in：解决泛型接口的类型兼容问题。out 表示返回值类型（只出），in 表示参数类型（只进）。

// 泛型类：T 是类型参数
public class Stack<T>
{
    private T[] items = new T[10];
    private int index = 0;

    public void Push(T item) => items[index++] = item;
    public T Pop() => items[--index];
}
// 使用：Stack<int> intStack = new Stack<int>();  // T 被替换为 int

// 泛型方法
public T Max<T>(T a, T b) where T : IComparable  // T 必须实现 IComparable
{
    return a.CompareTo(b) > 0 ? a : b;
}

// 泛型约束
public class Repository<T> where T : class, new()  // T 必须是引用类型且有无参构造
{
    public T Create() => new T();  // 因为 new() 约束，可安全调用 new T()
}

// 协变 out：T 只能出现在返回值（只读）
public interface IProducer<out T> { T Produce(); }
// IProducer<Dog> 可视为 IProducer<Animal>（Dog 是 Animal 的子类）

// 逆变 in：T 只能出现在参数（只写）
public interface IConsumer<in T> { void Consume(T item); }
// IConsumer<Animal> 可视为 IConsumer<Dog>（取 Animal 的消费者也能消费 Dog）

三、核心特性

3.1 委托与事件

委托是方法的类型安全引用，可以将方法当作变量传递。C# 提供预定义泛型委托 Action（无返回值）和 Func（有返回值），大部分场景无需自定义委托。

多播委托：同一个委托变量可通过 += 绑定多个方法，调用时会按注册顺序依次执行。

事件：基于委托的发布-订阅模式。和委托的关键区别是——事件只能在声明类内部 Invoke，外部只能 += / -=，更安全。

public delegate void LogHandler(string message);

// 内置委托：无需自定义，直接用 Action/Func

// 事件：类内部触发，外部只能订阅/取消
public class Button
{
    public event EventHandler Clicked;  // 声明事件

3.3 异常处理

异常是程序运行时的错误，C# 通过 try-catch-finally 机制处理。原则是捕获你能处理的异常，不要吞掉不该吞的错误。

using 语句：语法糖，等价于 try-finally + Dispose()。用于确保 IDisposable 对象（文件流、数据库连接等）被及时释放。

3.4 异步编程

异步编程让程序在等待 I/O 操作时不阻塞线程，提升响应性和吞吐量。核心关键字 async 和 await。

async/await 原理：await 碰到未完成的操作时，立即返回调用方，待操作完成后从断点继续执行。期间线程不会被占用，可处理其他请求。

Task.WhenAll / WhenAny：

  • WhenAny：任意一个完成就继续，可用于超时控制或最快响应

异步流 IAsyncEnumerable：C# 8+ 引入，用于异步地"逐个"产生数据，配合 await foreach 消费。

4.2 集合与数据结构

C# 集合分为泛型集合（System.Collections.Generic）和非泛型集合（System.Collections），优先使用泛型。

线程安全集合（System.Collections.Concurrent）：ConcurrentBag、ConcurrentDictionary、ConcurrentQueue 等，支持多线程安全操作。

8.2 OOP 三大特点

继承：子类继承父类的属性和方法，提高代码复用性。

8.7 GC 原理与优化

如何减少 GC 压力：

  • 减少 new 产生对象的次数（对象池、复用）
  • 使用 StringBuilder 代替字符串 +=
  • 避免在频繁调用的方法中创建临时对象
  • 使用结构体代替小对象（值类型不参与 GC）
  • 使用 WeakReference 持有可重建对象

工作原理：

  • 所有元素重新哈希分配到新桶

public class ObjectPool : MonoBehaviour
{
    [SerializeField] private GameObject prefab;
    private Queue<GameObject> pool = new Queue<GameObject>();

    public GameObject Get()
    {
        if (pool.Count > 0)
        {
            GameObject obj = pool.Dequeue();
            obj.SetActive(true);

        return Instantiate(prefab);

    {

    }
}
